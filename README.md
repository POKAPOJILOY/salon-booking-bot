# Бот записи частного мастера

Telegram-бот для мастера маникюра: принимает записи, напоминает о визите и через заданный срок приглашает клиента вернуться. Один экземпляр бота обслуживает одного мастера.

## Возможности

- Запись клиента: услуга → дата → время → имя → телефон → подтверждение.
- Атомарные перенос и отмена, защита от двойного бронирования через `BEGIN IMMEDIATE`.
- Ручные записи и блокировки времени мастером.
- Услуги, рабочая неделя, общий перерыв, шаг слотов и минимальный срок записи.
- Напоминания за 24 часа и 1 час, завершение визитов, повторные приглашения.
- Приглашение с интерактивными слотами Telegram Bot API 10.4 и кнопочным фолбэком.
- Ускоренное демо и статистика по источникам записей.
- SQLite: записи, настройки и флаги отправок сохраняются после перезапуска.

## Требования

- Python 3.11 или новее.
- Токен бота от [@BotFather](https://t.me/BotFather).
- Telegram ID мастера. Его можно узнать через [@userinfobot](https://t.me/userinfobot).

## Локальный запуск

1. Создайте бота в BotFather и получите токен.
2. Скопируйте файл настроек:

   ```bash
   cp .env.example .env
   ```

   В Windows можно скопировать файл в проводнике.

3. Заполните `.env`:

   ```dotenv
   BOT_TOKEN=123456:токен
   MASTER_ID=123456789
   TZ=Europe/Moscow
   DB_PATH=salon.db
   WIDGETS_ENABLED=true
   ```

4. Установите зависимости и запустите:

   ```bash
   python -m venv .venv
   # Linux/macOS:
   .venv/bin/pip install -r requirements.txt
   .venv/bin/python bot.py
   # Windows PowerShell:
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python bot.py
   ```

5. Откройте `/start` аккаунтом мастера. Сначала добавьте услугу и настройте расписание. Ссылку для клиентов выдаёт кнопка **«Моя ссылка»**.

`WIDGETS_ENABLED=false` полностью отключает только HTML-виджет; приглашения и запись по кнопкам продолжают работать. Если `sendWidget` не поддерживается конкретным клиентом или Bot API, бот автоматически отправляет обычные кнопки.

## Демо для встречи с мастером

1. Откройте `/start` аккаунтом `MASTER_ID`.
2. Нажмите **«Демо: прогнать сценарий»**. При необходимости бот создаст услугу «Маникюр» и рабочее расписание.
3. Через 10 секунд придёт уведомление о записи на завтра, через 20 секунд — демо-напоминание за 24 часа.
4. Примерно через 60 секунд придёт приглашение вернуться с ближайшими слотами.
5. Нажмите время прямо в виджете. Бот создаст запись без повторного ввода имени и телефона и уведомит мастера. На старом Telegram используйте **«Подобрать время»** под сообщением.
6. В настройках можно выключить **ДЕМО**. Пока режим включён, интерфейс мастера содержит пометку `ДЕМО`.

Демо-сообщения приходят в чат мастера. Для двух независимых сценариев создаются отдельные демо-клиенты, поэтому запись на завтра не блокирует приглашение из завершённого визита. Перед запуском убедитесь, что завтра есть хотя бы одно свободное окно.

## Ручная проверка основных блоков

### Запись, отмена и перенос

1. Откройте публичную ссылку другим аккаунтом и пройдите путь до подтверждения.
2. Убедитесь, что мастер получил карточку с услугой, временем, именем и телефоном.
3. Попробуйте занять пересекающееся время вторым аккаунтом: его не должно быть среди слотов.
4. Нажмите **«Перенести»**, выберите новые дату и время. Старая запись должна стать отменённой, новая — активной, мастер получает уведомление.
5. Нажмите **«Отменить»** и подтвердите. Время должно снова появиться в слотах, мастер получает уведомление.

### Админ-ядро

1. Добавьте запись вручную и убедитесь, что она видна в **«Записи»** и в статистике как `manual`.
2. Заблокируйте интервал, который ранее был свободен. Клиент не должен видеть пересекающиеся старты.
3. Добавьте услугу, выключите её и убедитесь, что она исчезла из клиентского выбора. Включите снова.
4. Настройте рабочие дни и общий перерыв; проверьте, что слоты вне часов и внутри перерыва не выдаются.
5. Сравните статистику за всё время и за 30 дней после записей по ссылке, вручную и по приглашению.

### Напоминания, перезапуск и приглашение

1. Для быстрой проверки используйте демо. Для боевой проверки создайте запись в подходящие интервалы: напоминания за 24 часа и 1 час должны прийти ровно один раз.
2. Перезапустите процесс. Записи и настройки должны остаться, пропущенные напоминания отправятся на первом цикле планировщика.
3. Нажмите **«Больше не напоминать»** в приглашении: следующих приглашений этому клиенту быть не должно.
4. При уже активной записи повторное приглашение не отправляется.
5. Отключите `WIDGETS_ENABLED` и повторите демо: путь на обычных кнопках должен остаться рабочим.

## Запуск на VPS через systemd

Пример рассчитан на Ubuntu/Debian и каталог `/opt/salon-booking-bot`:

```bash
sudo apt update
sudo apt install -y python3 python3-venv git
sudo git clone https://github.com/POKAPOJILOY/salon-booking-bot.git /opt/salon-booking-bot
cd /opt/salon-booking-bot
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env
sudo nano .env
sudo useradd --system --home-dir /opt/salon-booking-bot --shell /usr/sbin/nologin salon 2>/dev/null || true
sudo chown -R salon:salon /opt/salon-booking-bot
sudo chmod 600 .env
sudo cp deploy/salon-bot.service /etc/systemd/system/salon-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now salon-bot
sudo systemctl status salon-bot
journalctl -u salon-bot -f
```

Unit-файл запускает бот от отдельного пользователя `salon` без доступа к домашним каталогам. `Restart=always` восстанавливает процесс после сбоя, а планировщик догоняет пропущенные задачи.

Запускайте только один процесс на один файл SQLite. Резервную копию нужно делать у `salon.db` вместе с `salon.db-wal`, если WAL существует.

## Тесты

```bash
.venv/Scripts/python -m pytest -q       # Windows
.venv/bin/python -m pytest -q           # Linux/macOS
```

Покрыты генератор слотов, перерывы и границы рабочего дня, минимальный срок, гонка двух подключений, откат переноса, напоминания, повторные приглашения, демо, статистика, полный aiogram-сценарий, виджет, фолбэк, двойной тап и восстановление SQLite.

## Принятые решения

- Все моменты `start_at`, `end_at`, `created_at` хранятся в ISO 8601 UTC. Расписание и отображение используют `Europe/Moscow`.
- Перенос создаёт новую запись и отменяет старую в одной транзакции; источник записи сохраняется.
- Удаление услуги мягкое (`is_active=0`), чтобы история и статистика сохраняли название и цену.
- Выручка считается только по завершённым визитам. Отменённые записи не входят в количество записей по источникам и считаются отдельно.
- Период «30 дней» определяется по `created_at` записи.
- Виджет показывает до 7 ближайших окон на 14 дней и всегда сохраняет кнопочный фолбэк.
- Приглашение отправляется один раз; при блокировке бота клиенту ставится отказ от приглашений.
- Тексты сообщений вынесены в `texts.py`, кнопки собираются в `keyboards.py` и `admin.py`.
- Планировщик — простой `asyncio`-цикл с опросом каждые 60 секунд, внешний APScheduler не требуется.
