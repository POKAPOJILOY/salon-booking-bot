# Бот записи частного мастера

Telegram-бот для мастера маникюра: принимает записи, напоминает о визите и через заданный срок приглашает клиента вернуться. Один экземпляр бота обслуживает одного мастера.

## Возможности

- Запись клиента: услуга → дата → время → имя → телефон → подтверждение.
- Атомарные перенос и отмена, защита от двойного бронирования через `BEGIN IMMEDIATE`.
- Ручные записи и блокировки времени мастером: список блоков с удалением в два тапа, явная кнопка отмены на каждом шаге диалога.
- Текстовая карточка дня с эмодзи-структурой: записи с часами и источником, свободные окна диапазонами, перерывы и блоки, выручка; на перегруженном дне свободное сворачивается в сводку.
- Услуги, рабочая неделя, общий перерыв, шаг слотов и минимальный срок записи.
- Напоминания за 24 часа и 1 час, завершение визитов, повторные приглашения.
- Приглашение с интерактивными слотами Telegram Bot API 10.4 и кнопочным фолбэком.
- Ускоренное демо и статистика по источникам записей.
- SQLite: записи, настройки и флаги отправок сохраняются после перезапуска.

## Требования

- Python 3.11 или новее.
- Токен бота от [@BotFather](https://t.me/BotFather).
- Telegram ID мастера. Его можно узнать через [@userinfobot](https://t.me/userinfobot).

## Локальный запуск

1. Создайте бота в BotFather и получите токен.
2. Скопируйте файл настроек:

   ```bash
   cp .env.example .env
   ```

   В Windows можно скопировать файл в проводнике.

3. Заполните `.env`:

   ```dotenv
   BOT_TOKEN=123456:токен
   MASTER_ID=123456789
   TZ=Europe/Moscow
   DB_PATH=salon.db
   WIDGETS_ENABLED=false
   WEBAPP_PUBLIC_URL=https://<домен-проекта>.amvera.io
   WEBAPP_PORT=80
   ```

4. Установите зависимости и запустите:

   ```bash
   python -m venv .venv
   # Linux/macOS:
   .venv/bin/pip install -r requirements.txt
   .venv/bin/python bot.py
   # Windows PowerShell:
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python bot.py
   ```

5. Откройте `/start` аккаунтом мастера. Сначала добавьте услугу и настройте расписание. Ссылку для клиентов выдаёт кнопка **«Моя ссылка»**.

## Mini App (основной сценарий записи)

Telegram отключил HTML-виджеты в чатах, поэтому запись и расписание дня работают через Telegram Mini App (WebApp) — встроенную страницу, которую бот сам хостит на aiohttp в том же процессе, что и поллинг.

- `WEBAPP_PUBLIC_URL` — публичный HTTPS-домен проекта (на Amvera это выданный домен вида `<проект>.amvera.io` или свой подключённый домен). Бот подставляет его в кнопки `web_app`: приглашение «📅 Выбрать время», кнопка «📅 Записаться» у `/start` и «🗓 Открыть день» в карточке дня мастера.
- Если `WEBAPP_PUBLIC_URL` пуст — кнопки Mini App не показываются, бот работает старым сценарием inline-кнопок, aiohttp-сервер не поднимается.
- `WEBAPP_PORT` — порт встроенного сервера (на Amvera `80`, проброшен в `amvera.yml` как `containerPort`).
- Все `/api/*`-эндпоинты проверяют `initData` Telegram (HMAC-SHA256, `auth_date` не старше 24 часов); разделы мастера (`/api/day*`) дополнительно требуют `user.id == MASTER_ID`.

Локальная проверка сервера без Telegram:

```bash
WEBAPP_PUBLIC_URL=http://localhost:8080 WEBAPP_PORT=8080 python bot.py
# страница: http://localhost:8080/app (API без initData отвечает 401 — это нормально)
```

На Windows порт 80 может требовать прав администратора — для локального запуска используйте `WEBAPP_PORT=8080`.

`WIDGETS_ENABLED` управляет только старыми HTML-виджетами (по умолчанию `false`, код сохранён в репозитории). При `true` и отсутствии `WEBAPP_PUBLIC_URL` приглашения и уведомления снова уходят виджетами, с фолбэком на кнопки.

BotFather: дополнительной настройки не нужно; при желании можно назначить menu button на тот же URL (`/setmenubutton` → web app), но бот этого не требует.

## Демо для встречи с мастером

1. Откройте `/start` аккаунтом `MASTER_ID` и нажмите **«🎬 Демо»**.
2. Выберите **«▶️ Полный прогон»**: через 10 секунд придёт новая запись, через 20 секунд — напоминание, примерно через 60 — приглашение вернуться.
3. Приглашение вернуться приходит с кнопкой **«📅 Выбрать время»**: она открывает Mini App с уже выбранной услугой и ценой — мастер может сам тапнуть и пройти путь клиента до экрана «Вы записаны!». Без `WEBAPP_PUBLIC_URL` приглашение работает на обычных inline-кнопках.
4. **«📊 Показать перегруженный день»** создаёт 8 записей, перерыв и блоки: текстовая карточка дня + кнопка **«🗓 Открыть день»** ведёт в Mini App забитого дня.
5. **«🙋‍♀️ Сыграть клиента»** по шагам показывает путь от ссылки до возврата через 3 недели с продающими пояснениями.
6. **«Выключить ДЕМО и очистить данные»** удаляет только помеченные демо-записи, клиентов, блоки и автоматически созданную демо-услугу. Реальные данные не затрагиваются.

Демо-сообщения приходят в чат мастера. Для полного прогона нужно свободное окно завтра. При включённом режиме интерфейс мастера содержит пометку `ДЕМО`.

## Ручная проверка основных блоков

У мастера под полем ввода постоянно находятся 9 кнопок меню, у клиента — **«📝 Записаться»** и **«📋 Мои записи»**. После создания, переноса, отмены, блокировки и изменения настроек бот показывает «✅ Готово… Что дальше?» с контекстными кнопками. Проверьте пять таких действий подряд: ни одно не должно заканчиваться экраном без следующего шага. Нажатие любой кнопки меню во время диалога отменяет его и сразу открывает выбранный раздел — ошибок валидатора быть не должно.

### Запись, отмена и перенос

1. Откройте публичную ссылку другим аккаунтом и пройдите путь до подтверждения через **«📝 Записаться»**.
2. Убедитесь, что мастер получил карточку с услугой, временем, именем и телефоном.
3. Попробуйте занять пересекающееся время вторым аккаунтом: его не должно быть среди слотов.
4. Откройте **«📋 Мои записи»**, нажмите **«Перенести»** и выберите новые дату и время. Старая запись должна стать отменённой, новая — активной, мастер получает уведомление.
5. Нажмите **«Отменить»** и подтвердите. Время должно снова появиться в слотах, мастер получает уведомление. Нижнее меню должно оставаться на месте, в том числе после отправки контакта.

### Админ-ядро

1. Добавьте запись через **«➕ Добавить запись»**. Откройте **«📋 Записи»**: в карточке дня должны быть иконка источника, клиент, услуга, свободные окна и выручка дня.
2. Полистайте дни кнопками **«⬅ Вчера»**, **«Сегодня»**, **«Завтра ➡»** и проверьте **«📅 Выбрать дату»**.
3. Нажмите кнопку записи для отмены: сначала должно появиться подтверждение, затем «✅ Готово… Что дальше?».
4. Заблокируйте интервал через **«🔒 Блок время»**. В карточке дня появится `🚫`, а клиент перестанет видеть пересекающиеся старты.
5. Добавьте услугу, выключите её и убедитесь, что она исчезла из клиентского выбора. Включите снова.
6. Откройте **«🕐 Расписание»**: одинаковые дни объединяются в диапазоны, перерыв записан текстом, сегодня помечено отдельно. Кнопки **«Пн–Вс»** сразу открывают редактирование выбранного дня.
7. Сравните статистику за всё время и за 30 дней после записей по ссылке, вручную и по приглашению.

### Напоминания, перезапуск и приглашение

1. Для быстрой проверки используйте демо. Для боевой проверки создайте запись в подходящие интервалы: напоминания за 24 часа и 1 час должны прийти ровно один раз.
2. Перезапустите процесс. Записи и настройки должны остаться, пропущенные напоминания отправятся на первом цикле планировщика.
3. Нажмите **«Больше не напоминать»** в приглашении: следующих приглашений этому клиенту быть не должно.
4. При уже активной записи повторное приглашение не отправляется.
5. Отключите `WIDGETS_ENABLED` и повторите демо: путь на обычных кнопках должен остаться рабочим.

## Запуск на VPS через systemd

Пример рассчитан на Ubuntu/Debian и каталог `/opt/salon-booking-bot`:

```bash
sudo apt update
sudo apt install -y python3 python3-venv git
sudo git clone https://github.com/POKAPOJILOY/salon-booking-bot.git /opt/salon-booking-bot
cd /opt/salon-booking-bot
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env
sudo nano .env
sudo useradd --system --home-dir /opt/salon-booking-bot --shell /usr/sbin/nologin salon 2>/dev/null || true
sudo chown -R salon:salon /opt/salon-booking-bot
sudo chmod 600 .env
sudo cp deploy/salon-bot.service /etc/systemd/system/salon-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now salon-bot
sudo systemctl status salon-bot
journalctl -u salon-bot -f
```

Unit-файл запускает бот от отдельного пользователя `salon` без доступа к домашним каталогам. `Restart=always` восстанавливает процесс после сбоя, а планировщик догоняет пропущенные задачи.

Запускайте только один процесс на один файл SQLite. Резервную копию нужно делать у `salon.db` вместе с `salon.db-wal`, если WAL существует.

## Тесты

```bash
.venv/Scripts/python -m pytest -q       # Windows
.venv/bin/python -m pytest -q           # Linux/macOS
```

Покрыты генератор слотов, перерывы и границы рабочего дня, минимальный срок, гонка двух подключений, откат переноса, напоминания, повторные приглашения, демо, статистика, полный aiogram-сценарий, виджет, фолбэк, двойной тап, восстановление SQLite и Mini App (валидация initData, запись через API, день мастера, отмена).

## Принятые решения

- Все моменты `start_at`, `end_at`, `created_at` хранятся в ISO 8601 UTC. Расписание и отображение используют `Europe/Moscow`.
- Перенос создаёт новую запись и отменяет старую в одной транзакции; источник записи сохраняется.
- Удаление услуги мягкое (`is_active=0`), чтобы история и статистика сохраняли название и цену.
- Выручка считается только по завершённым визитам. Отменённые записи не входят в количество записей по источникам и считаются отдельно.
- Период «30 дней» определяется по `created_at` записи.
- Виджет показывает до 7 ближайших окон на 14 дней и всегда сохраняет кнопочный фолбэк.
- Приглашение отправляется один раз; при блокировке бота клиенту ставится отказ от приглашений.
- Тексты сообщений вынесены в `texts.py`, кнопки собираются в `keyboards.py` и `admin.py`.
- Планировщик — простой `asyncio`-цикл с опросом каждые 60 секунд, внешний APScheduler не требуется.
